## 💻 3. 核心實作原始碼 (Core Code Enforcement)

### 3.1 執行期硬體感知器：`src/config/hardware.py`
```python
import os
import psutil
import torch

class RuntimeHardwareDetector:
    @staticmethod
    def detect_device() -> str:
        if torch.backends.mps.is_available():
            return "mps"
        elif torch.cuda.is_available():
            return "cuda"
        return "cpu"

    @staticmethod
    def calculate_optimal_threads(device: str) -> int:
        physical_cores = psutil.cpu_count(logical=False)
        if not physical_cores:
            physical_cores = 4
        
        if device == "mps":
            return max(1, physical_cores)
        elif device == "cuda":
            return max(1, physical_cores * 2)
        else:
            return max(1, physical_cores - 1)
```

### 3.2 Pydantic v2 強型態防禦閘門：`src/config/schema.py`
```python
from pydantic import BaseModel, Field, field_validator, model_validator
from typing import Literal
from src.config.hardware import RuntimeHardwareDetector

class HyperParametersSchema(BaseModel):
    r: int = Field(..., description="LoRA 內部的低秩矩陣 Rank 階數")
    alpha: int = Field(..., description="LoRA 縮放因子常數 Scaling Factor")
    lr: float = Field(..., description="優化器初始學習率")
    max_seq_len: int = Field(..., description="最大上下文 Token 輸入長度")

    @field_validator("r")
    @classmethod
    def validate_rank(cls, v: int) -> int:
        if v <= 0 or (v & (v - 1)) != 0:
            raise ValueError(f"LoRA Rank 必須為大於 0 的 2 的冪次方，當前非法輸入值: {v}")
        return v

    @field_validator("lr")
    @classmethod
    def validate_lr(cls, v: float) -> float:
        if not (1e-6 <= v <= 1e-2):
            raise ValueError(f"學習率 lr 超出安全邊界限制 [1e-6, 1e-2]，當前非法輸入值: {v}")
        return v

    @field_validator("max_seq_len")
    @classmethod
    def validate_seq_len(cls, v: int) -> int:
        if v <= 0 or v > 8192:
            raise ValueError(f"不支援的上下文長度限制，當前輸入值: {v}")
        return v


class AppConfigSchema(BaseModel):
    project_name: str = Field(..., description="專案識別名稱")
    debug: bool = Field(default=True, description="除錯模式開關")
    hparams: HyperParametersSchema = Field(..., description="巢狀超參數物件")
    
    device: Literal["mps", "cuda", "cpu"] = "cpu"
    optimal_threads: int = Field(default=4, ge=1)

    @model_validator(mode="before")
    @classmethod
    def inject_runtime_hardware(cls, data: dict) -> dict:
        if isinstance(data, dict):
            detected_device = RuntimeHardwareDetector.detect_device()
            optimal_threads = RuntimeHardwareDetector.calculate_optimal_threads(detected_device)
            data["device"] = detected_device
            data["optimal_threads"] = optimal_threads
        return data
```

### 3.3 系統主程序進入點：`main.py`
```python
import hydra
from omegaconf import DictConfig, OmegaConf
import torch
import sys
from src.config.schema import AppConfigSchema

@hydra.main(version_base=None, config_path="config", config_name="config")
def main(cfg: DictConfig) -> None:
    print("==================================================")
    print("🚀 [Module 01] 初始化 MLOps 強型態組態管理核心...")
    print("==================================================")

    raw_config_dict = OmegaConf.to_container(cfg, resolve=True)
    
    try:
        validated_config = AppConfigSchema.model_validate(raw_config_dict)
    except Exception as e:
        print("❌ [CRITICAL] 組態校驗未通過！安全阻斷核心程序啟動。", file=sys.stderr)
        print(f"詳細錯誤報告:
{e}", file=sys.stderr)
        sys.exit(1)

    print("✅ 組態型態安全檢查通過！")
    print(f"|-- 專案名稱: {validated_config.project_name}")
    print(f"|-- 執行硬體: {validated_config.device.upper()}")
    print(f"|-- 計算核心執行緒鎖定: {validated_config.optimal_threads} Threads")
    print(f"|-- LoRA 配置效益: Rank={validated_config.hparams.r}, Alpha={validated_config.hparams.alpha}")
    print(f"|-- 初始學習率: {validated_config.hparams.lr}")
    print("--------------------------------------------------")

    torch.set_num_threads(validated_config.optimal_threads)
    print(f"⚙️  成功將 torch.set_num_threads 鎖定為: {torch.get_num_threads()}")

if __name__ == "__main__":
    main()
```

## 📈 4. 效能指標觀測與踩坑排除 (Profiling & Troubleshooting)

### 4.1 邊界破壞測試 (Destructive Security Testing)
當刻意更改 `config/hparams/ryan_lora.yaml` 內的數值，觀察 Pydantic v2 的精準防守表現：

* **案例 A：將 `r` 改為 `7`（非 2 的冪次方）**
  * *預期系統拋出錯誤：* `Value error, LoRA Rank 必須為大於 0 的 2 的冪次方，當前非法輸入值: 7`
  * *效益：* 成功在模型初始化前攔截不符合矩陣張量計算對齊的參數，避免執行到第 3 點訓練迴圈時才因為 Shape 不對稱而崩潰。

* **案例 B：將 `lr` 改為 `0.5`（超出邊界）**
  * *預期系統拋出錯誤：* `Value error, 學習率 lr 超出安全邊界限制 [1e-6, 1e-2]`
  * *效益：* 防止開發人員筆誤導致訓練初期的權重直接爆掉 (NaN)。

### 4.2 Apple Silicon (M4 Pro) 效能觀測紀錄
* **未鎖定 Thread 狀態 (預設) :** PyTorch 預設會調用所有核心（包括 E-cores 效率核心），在大型矩陣計算中導致極其高頻的 Context Switch。使用 `top` 觀測發現 CPU 佔用率虛高，但吞吐量下降。
* **鎖定實體 Thread 狀態 (本實作) :** 通過 `psutil.cpu_count(logical=False)` 將線程緊緊錨定在實體 P-cores（效能核心）數量。矩陣運算與 Dataloader 載入時，預期將降低約 **12% ~ 15%** 的上下文切換損耗，最大化每瓦效能表現。
