# 📑 08.4.5 銜接日誌：從本地權重微調（Training）到偏好對齊（Alignment）的架構躍遷

> 本篇作為模組四（微調核心）與模組五（對齊引擎）之間的架構橋樑。我們將定義如何將微調階段獲得的「基礎領域智慧」進一步收攏、轉化為符合人類意志的「偏好對齊增量」，並釐清從單一模型權重優化演進到雙軌模型（Policy & Reference）並行查表時的記憶體防禦與通訊解耦機制。

## 🧭 1. 任務特徵躍遷：從單一權重優化到雙軌模型賽局

在模組四中，我們的戰場聚焦於如何透過手寫 `MockLinearWithLoRA` 對單一模型進行低秩矩陣的權重更新（Compute-Bound）。進入模組五後，我們不只要求模型「學會知識」，更要求模型「明辨是非」。

這是一次從**單一模型梯度更新**到**雙軌模型（Policy 策略網絡與 Reference 參考網絡）聯動查表**的範式躍遷。

### 資源與控制調度對比矩陣

|**維度**|**模組四：LoRA Training**|**模組五：Direct Preference Optimization (DPO)**|
|---|---|---|
|**數學目標**|最小化預測誤差（如 MSE/CrossEntropy），累積基礎梯度|最大化隱式獎勵差（Delta Reward），拉開 Chosen 與 Rejected 分佈|
|**記憶體佈局**|**單軌模型**：僅解鎖活躍低秩小表（LoRA A/B），Base Model 唯讀常駐|**雙軌模型**：Policy（可變）與 Reference（凍結）兩套模型同時定址，記憶體開銷翻倍|
|**前向傳播次數**|單次 Forward Pass（處理單一輸入特徵）|4 次 Forward Pass（Policy / Ref 分別處理 Chosen / Rejected 資料）|
|**計算核心**|Token-Level 特徵映射與降維傳送帶|Logits 矩陣對數機率（Log Likelihood）的多維 `gather` 算子提取|

## 🔄 2. 資料平面與資產狀態機流轉 (Asset Flow Contract)

為了維護 MLOps 鏈路的極致純粹，模組四微調產出的輕量增量結晶（`lora_weights.pt`），將作為模組五雙軌對齊鏈路的「初始化起跑點」。

### 資料流轉生命週期與狀態機

```
[ 落地檔案：ryan_lora_checkpoint.pt ]  <-- 模組四產出的輕量增量結晶 (唯讀輸入)
       │
       ▼ [狀態：LORA_WEIGHT_CHECKPOINT]
       │  加載至 Policy 模型作為初始化權重；Ref 模型則保持 Base 狀態並全面鎖死梯度
       │
       ▼ (進入模組五：讀取 Preference 偏好三元組數據)
[ 狀態：PREFERENCE_TRIAD_TENSORS ] 
       │  將 {"prompt", "chosen", "rejected"} 轉化為實體 Token Tensor
       │
       ▼ (進入對齊迴路：4路前向分流與 Token-Level 對數機率提取)
[ 狀態：LOG_LIKELIHOOD_EXTRACTED ]
       │  透過手寫 DirectPreferenceLoss，利用機率差隱式拉開獎勵分佈
       │
       ▼ 產生對齊權重：dpo_aligned_lora.pt
[ 狀態：DPO_ALIGNED_INCREMENT ]
```

- **狀態：LORA_WEIGHT_CHECKPOINT**：模組四透過手寫訓練迴圈，將特定領域的知識壓縮進 LoRA 的活躍增量小表中。
    
- **狀態：DPO_ALIGNED_INCREMENT**：進入模組五後，系統透過 `DirectPreferenceLoss` 引入隱式 KL 懲罰係數 $\beta$，以模組四的成果為起點，將智慧收攏至符合人類安全的偏好邊界內。
    

## 🔀 3. 程式執行控制流 (Program Control Flow)

以下為從模組四完工，到拉起模組五進行雙軌賽局對齊的系統初始化與控制順序圖：

```
sequenceDiagram
    autonumber
    actor Architect as 系統進入點 (run_dpo.py)
    participant Boot as Bootstrap (load_dotenv)
    participant Schema as Pydantic v2 校驗閘門
    participant ModelFactory as 雙軌模型工廠
    participant DPOEngine as DirectPreferenceLoss 引擎
    participant Pipeline as DPOTrainingPipeline

    Architect->>Boot: 1. 於最頂層觸發 load_dotenv()，防範全域組態污染
    Architect->>Schema: 2. 反序列化並校驗 hparams.dpo_beta 參數
    Schema-->>Architect: 校驗通過，注入強型態 DPO 配置組態
    
    Architect->>ModelFactory: 3. 初始化雙軌定址空間 (Policy & Reference)
    Note over ModelFactory: Policy 載入模組四 Checkpoint (解鎖 LoRA)<br/>Reference 全生命週期鎖死梯度 (requires_grad=False)
    
    Architect->>DPOEngine: 4. 實例化 Token-Level 對數機率提取核心
    Architect->>Pipeline: 5. 啟動 DPO 偏好對齊控制管線
    
    loop 偏好數據迭代 (Step / Epoch)
        Pipeline->>Pipeline: a. 驅動 Policy Forward (Chosen + Rejected)
        Pipeline->>Pipeline: b. 用 torch.no_grad() 阻斷驅動 Ref Forward (防爆內存)
        Pipeline->>DPOEngine: c. 多維 gather 算子提取 Log P
        Pipeline->>Pipeline: d. 最小化二元交叉熵損失並執行梯度裁剪
    end
    Pipeline-->>Architect: 6. 對齊完工，吐出淨優化偏好差 (Delta Reward) 報告
```

## 🛡️ 4. 模組五「對齊過渡期」架構防禦焦點 (Pre-flight Checklist)

在啟動模組五程式碼前，架構師必須在專案的過渡控制鏈路中死死卡緊以下防禦機制，絕不允許任何安全盲區：

- **計算圖阻斷鐵律（Reference Graph Block）：**
    
    不同於模組四隻需要維護一套優化器狀態，模組五在執行 Reference Model 的前向傳播時，**必須顯式使用 `with torch.no_grad():` 進行物理性截斷**。否則，凍結端的機率矩陣（Logits）會盲目累積計算圖快取，導致顯存或 Unified Memory 在單步內瞬時觸發 OOM 崩潰。
    
- **標籤恆等比對合約（Token Alignment Contract）：**
    
    在手寫 `_get_batch_logps` 提取器時，機率矩陣的維度為 $[B, S, V]$，而標籤矩陣維度為 $[B, S]$。架構上必須強制執行 `assert logits.shape[:2] == labels.shape` 的強型態防禦閘門，杜絕因 Tokenizer 填充（Padding）不一致導致多維 `gather` 算子發生索引越界（`IndexError`）。
    
- **超參數震盪守護（Beta Boundary Protection）：**
    
    聯動約束防禦閘門 `schema.py` 必須對 `dpo_beta` 施加 `@field_validator("dpo_beta")` 限制，**下限嚴禁低於 0.01**。若 Beta 過小，隱式獎勵的訊號增益將極度放大，導致訓練步進（Step-Loss）發生不可逆的激進震盪。
    
- **異質序列化防禦（Cross-Platform Serialization）：**
    
    延續模組四的資產導出規範，不論是在 `mps` 還是 `cuda` 晶片上完成對齊，導出權重前必須**強制執行 `.cpu()` 拉回作業系統主內存**，抹除裝置憑證後方可進行 `torch.save()`，確保資產在跨平台異質反序列化時的绝对安全。
