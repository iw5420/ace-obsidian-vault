
> 模組一（動態組態與型態安全架構）之依賴套件安裝指令、版本鎖定規範與執行期控制用途說明。

## 🚀 快速安裝指令

在初始化開發環境時，請於 Python 虛擬環境（建議使用 conda 或 venv）中執行以下指令安裝核心依賴：

```
pip install pydantic==2.10.0 hydra-core==1.3.2 omegaconf==2.3.0 psutil==5.9.8 torch==2.3.0
```

## 📋 套件用途與執行期架構對齊說明

本模組的核心在於建立「強型態防禦閘門」與「動態硬體感知器」。以下為各個依賴套件在本模組程式碼中的實體落實位置與關鍵技術考量：

### 1. `pydantic` (v2.10.0)

- **落實位置：** `src/config/schema.py` 中的 `HyperParametersSchema` 與 `AppConfigSchema`。
    
- **核心功能：**
    
    - **強型態攔截 (Type Enforcement)：** 確保傳入的參數型態完全符合預期，若傳入非法的型態（例如將學習率傳成字串 `"high"`），會直接在初始化階段拋出 `ValidationError` 進行安全阻斷。
        
    - **超參數邊界校驗 (Boundary Validation)：** 透過 `@field_validator` 驗證 LoRA 關鍵參數（如確保 Rank $r$ 必須是 2 的冪次方、學習率 $lr$ 落在安全區間 $[10^{-6}, 10^{-2}]$），防止無效組態進入後續耗費數十小時的訓練流程。
        
    - **執行期狀態注入 (Runtime Injection)：** 透過 `@model_validator(mode="before")` 在解析前調用硬體探針，動態將系統偵測到的執行設備與最優執行緒數（Threads）寫入配置物件中，完成組態閉環。
        

### 2. `hydra-core` (v1.3.2)

- **落實位置：** `main.py` 中的 `@hydra.main` 裝飾器與實體組態目錄 `config/`。
    
- **核心功能：**
    
    - **階層式組態管理 (Hierarchical Configuration)：** 負責將全局設定（`config.yaml`）、超參數設定（`ryan_lora.yaml`）以及環境設定（`dev.yaml`）進行無縫組合。
        
    - **CLI 動態覆蓋 (CLI Override)：** 允許在終端機啟動程序時（例如 `python main.py hparams.lr=1e-4`），動態覆蓋 YAML 配置，且不需手動修改實體檔案，這在自動化排程與超參數掃描時極為關鍵。
        

### 3. `omegaconf` (v2.3.0)

- **落實位置：** `main.py` 進入點中的 `OmegaConf.to_container(cfg, resolve=True)`。
    
- **核心功能：**
    
    - **動態變數解析 (String Interpolation & Resolve)：** YAML 檔案中若有動態變數引用（如 `${hparams.r}`）或環境變數讀取，必須透過 `resolve=True` 強制將其解析為實體數值。
        
    - **資料結構轉換：** 將 Hydra 原生的 `DictConfig` 物件轉換為 Python 標準字典（`dict`），以便 Pydantic 能無縫讀取並進行驗證。
        

### 4. `psutil` (v5.9.8)

- **落實位置：** `src/config/hardware.py` 中的 `psutil.cpu_count(logical=False)`。
    
- **核心功能：**
    
    - **Apple Silicon 效能核鎖定 (P-Cores Binding)：** Apple 的 M 系列晶片（如 M4 Pro）採用大小核心設計（P-cores 與 E-cores）。如果使用 Python 原生的 `os.cpu_count()`，會連節能核心（E-cores）一起計入，導致計算執行緒爭搶與高度 Context Switch。`psutil` 用於精確獲取**實體效能核心數**，將運算資源錨定在高頻核心上。
        

### 5. `torch` (v2.3.0)

- **落實位置：** `src/config/hardware.py` 中的偵測邏輯，與 `main.py` 尾端的 `torch.set_num_threads()`。
    
- **核心功能：**
    
    - **加速晶片感知：** 透過 `torch.backends.mps.is_available()` 動態偵測當前環境是否支援 Apple Silicon 的金屬圖形加速（MPS），或 NVIDIA 的 CUDA 運算，以動態配置最適合的底層。
        
    - **Thread 生效控制：** 在偵測並計算出最優執行緒後，調用 `torch.set_num_threads(optimal_threads)` 來限制 PyTorch 全局並行線程，徹底避免硬體資源過度分配產生的抖動。
        

## ⚙️ 環境驗證檢查點 (Sanity Check)

在虛擬環境中安裝完上述套件後，請執行以下單行命令，以確保您的 Runtime 環境已能精確對齊：

```
python -c "import torch, psutil; print('--- Runtime Sanity Check ---'); print('MPS Available:', torch.backends.mps.is_available()); print('Physical Cores:', psutil.cpu_count(logical=False))"
```

### 預期輸出範例：

- **Apple Silicon M 系列設備：**
    
    ```
    --- Runtime Sanity Check ---
    MPS Available: True
    Physical Cores: 8 (依實際晶片規格顯示)
    ```
    
- **無 GPU 加速設備：**
    
    ```
    --- Runtime Sanity Check ---
    MPS Available: False
    Physical Cores: 4
    ```
