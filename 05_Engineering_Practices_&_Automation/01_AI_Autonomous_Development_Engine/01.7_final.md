要在你的 Windows 環境實作這套 Harness 機制，你可以寫一組簡單的 **Python 自動化協調腳本**（利用 `python-gitlab` 庫），或是透過 GitLab 的 **GitLab Runner (Docker Executor)** 直接在本地跑 CI 流程。

### 1. 建立專案的「韁繩文件」

在你的 Java 專案根目錄，建立 `.agentic/` 資料夾，放置以下檔案：

- `instructions.md`：寫明專案是 Spring Boot 3.x / Spring Cloud、使用什麼資料庫、要求 Clean Code、必須 TDD 執行。
    
- `architecture_rules.md`：寫明套件依賴規範（例如：`controller` 只能呼叫 `service`，絕對不能直接呼叫 `repository`），供 Gemini Review 時作為檢查依據。
    

### 2. Docker 沙盒常駐命令

在 Windows 啟動一個專屬的開發沙盒，保持 Mount 掛載：

Bash

```
docker run -d --name java-dev-sandbox -v C:\your-projects\java-app:/workspace -w /workspace maven:3.9-eclipse-temurin-17 tail -f /dev/null
```

當本地的 Claude Code（透過 Windows 終端機執行）修改完程式碼後，腳本或 Claude 本地工具可以直接呼叫：

Bash

```
docker exec java-dev-sandbox mvn clean test
```

### 3. 計畫書範本格式 (`PLAN.md`)

嚴格限制 Gemini 在 Phase 2 生成的計畫書格式。只要格式固定，AI Agent 就能輕易解析：

Markdown

```
# Agent Execution Plan - Issue #101

## 1. Core Objective
- [ ] 實作 Kafka 既有 Consumer 的冪等性檢核，防止重複消費。

## 2. Architectural Boundary & Skills
- Skill: Spring Boot, Redis Distributed Lock
- Boundary: Only modify `com.ace.messaging.consumer` package.

## 3. TDD Test Cases to Add
- [ ] testConsume_Success_FirstTime()
- [ ] testConsume_Ignored_DuplicateKey()

## 4. Modified Files
- `src/main/java/com/ace/messaging/consumer/OrderConsumer.java`
```

這套架構完美契合了 **Harness Engineering** 的核心精髓：**AI 負責高速產出與自我修正，人類透過「審查計畫書」與「最終 MR 核可」握緊韁繩，而結構化的測試沙盒與獨立的 Reviewer Agent 則成了拉緊韁繩的物理機制。**
