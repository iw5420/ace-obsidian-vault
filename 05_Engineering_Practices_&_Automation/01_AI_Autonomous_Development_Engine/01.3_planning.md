這是落實 Harness Engineering 最核心的一步——將計畫視為**一等公民（First-class artifact）**。

**1.生成結構化計畫書：**Gemini Pro 負責。

結合 Phase 1 的分析，Gemini 生成 `PLAN.md` 結構化文字，內容必須包含：

- **Objective**: 明確的功能目標。
    
- **Test Cases**: 預計新增的 TDD 測試案例與邊界條件。
    
- **Changes**: 預計修改的檔案、類別、介面宣告。
    

**2.發起 GitLab 討論：**人類介入。

腳本自動將 `PLAN.md` 內容作為 Comment 貼到 GitLab Issue #101，並將 Issue 打上 `status::waiting-human-plan-approval` 標籤。

**3.修正與定稿：**人機共創。

你在 Issue 下方回覆修正意見（例如：「_不要修改 A 介面，改從 B 擴充_」）。Gemini 讀取回覆，更新計畫書。

**4.核准計畫並開分支：**啟動執行。

當你回覆 `Approved` 後，自動化腳本調用 GitLab API 自動建立 Feature Branch `feature/issue-101`，並將最新版的 `PLAN.md` **直接 Commit 進入該分支根目錄**。
