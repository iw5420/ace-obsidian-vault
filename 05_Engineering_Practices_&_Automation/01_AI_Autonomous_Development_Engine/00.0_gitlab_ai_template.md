# GitLab AI Template 設計規範

本文件記錄 **ai-template** 倉庫的設計方式，涵蓋三種技術棧：**Python FastAPI**、**Java Spring Boot**、**React TypeScript**。

**架構核心概念**：Template 管理與 AI 自動化引擎是兩件獨立的事。

|倉庫|職責|包含內容|
|---|---|---|
|`ai-engine`|AI 自動化執行引擎|`mcp_orchestrator.mjs`、`mcp_config.json`|
|`ai-template`|Template 管理與開新專案工具|三種技術棧 template + 本地建立工具（`tools/`）|

各業務專案從 `ai-template` 建立，建立後與 template 無關聯，獨立演進。

## 1. 倉庫命名與 GitLab 設定

### 1.1 倉庫結構

在 GitLab 組織底下建立一個 `ai-template` 倉庫，內部以子目錄區分技術棧：

```
ai-template/                      # 單一倉庫，統一管理所有 template
├── tools/                        # 本地建立工具（Node.js）
│   ├── server.js                 # 後端：讀 template、複製檔案、執行 git
│   ├── project-creator.html      # 前端介面
│   └── package.json              # 依賴（只需要 express）
├── fastapi/                      # Python FastAPI template
├── springboot/                   # Java Spring Boot template
└── react/                        # React TypeScript template
```

## 3. tools/ 本地建立工具

`tools/` 是一個輕量的本地 Node.js 工具，透過瀏覽器介面選擇 template，在本機直接建立新專案目錄、複製 template 內容並初始化 git。**不依賴任何雲端 API，與 GitLab / GitHub / 任何 Git 平台皆相容。**

### 3.1 前置需求

- **Node.js 18+**：[nodejs.org](https://nodejs.org/) 下載安裝
- **Git**：確認 `git` 指令可在終端機執行
- **`ai-template` 倉庫已 clone 到本機**

### 3.2 啟動工具

第一次使用，在 `tools/` 目錄安裝依賴：

```bash
cd ai-template/tools
npm install
```

之後每次啟動：

```bash
node server.js
```

看到以下畫面即代表成功：

```
  ╔══════════════════════════════════════╗
  ║   ai-template 專案建立工具             ║
  ║   http://localhost:3000              ║
  ║   Ctrl+C 關閉伺服器                    ║
  ╚══════════════════════════════════════╝
```

開啟瀏覽器前往 `http://localhost:3000`。

### 3.3 操作流程

**步驟 1：選擇 Template**

點選對應的技術棧卡片：

- 🐍 **Python** → 從 `fastapi/` 複製
- ☕ **Java** → 從 `springboot/` 複製
- ⚛️ **React** → 從 `react/` 複製

**步驟 2：填入專案設定**

|欄位|說明|範例|
|---|---|---|
|專案名稱|新資料夾的名稱|`gov-tender-scraper`|
|輸出路徑|新資料夾要建在哪個目錄下|`C:\projects` 或 `/Users/you/projects`|
|遠端 Repo URL|選填，填了會自動 push|`https://gitlab.example.com/your-org/your-project.git`|

**步驟 3：按下「建立專案」**

`server.js` 自動執行：

```
複製 template 檔案到新目錄
        ↓
git init
        ↓
git add -A
        ↓
git commit -m "init: bootstrap from ai-template/{template}"
        ↓
（若有填遠端 URL）git remote add origin + git push
```

完成後顯示新專案的本機路徑。

**步驟 4：設定遠端（若步驟 2 未填 URL）**

若沒有在工具裡填遠端 URL，事後在 GitLab / GitHub 建立空白倉庫後手動執行：

```bash
cd {輸出路徑}/{專案名稱}
git remote add origin https://gitlab.example.com/your-org/your-project.git
git push -u origin main
```

**步驟 5：建立後確認清單**

前往專案目錄確認以下檔案都存在：

- [ ] `.gitlab-ci.yml`
- [ ] `.gitignore`
- [ ] `CLAUDE.md`
- [ ] `.agentic/instructions.md`
- [ ] `.agentic/architecture_rules.md`

### 4.2 .gitlab-ci.yml

```yaml
stages:
  - init

ai_pipeline_init:
  stage: init
  image: node:20-slim
  before_script:
    - apt-get update && apt-get install -y curl git
    - npm install @modelcontextprotocol/sdk @google/genai
    - mkdir -p .agentic/runtime
    # 版本固定：修改 ENGINE_VERSION 以升級引擎，升級為明確的人類決策
    - ENGINE_VERSION="v1.0.0"
    - BASE_URL="http://10.0.0.10/ai-test/ai-engine/-/raw/${ENGINE_VERSION}"
    - |
      curl -sf --header "PRIVATE-TOKEN: ${PROJECT_ACCESS_TOKEN}" "${BASE_URL}/mcp_orchestrator.mjs" -o .agentic/runtime/mcp_orchestrator.mjs \
        || { echo "[-] 致命錯誤：無法下載引擎腳本，請確認版本 ${ENGINE_VERSION} 存在"; exit 1; }
    - |
      curl -sf --header "PRIVATE-TOKEN: ${PROJECT_ACCESS_TOKEN}" "${BASE_URL}/mcp_config.json" -o .agentic/runtime/mcp_config.json \
        || { echo "[-] 致命錯誤：無法下載 MCP 配置，請確認版本 ${ENGINE_VERSION} 存在"; exit 1; }
  script:
    - node .agentic/runtime/mcp_orchestrator.mjs --tech-stack python
  rules:
    - if: '$CI_PIPELINE_SOURCE == "trigger" || $CI_PIPELINE_SOURCE == "webhook"'
      when: always
  variables:
    GITLAB_API_URL: "$CI_API_V4_URL"
    GITLAB_TOKEN: "$PROJECT_ACCESS_TOKEN"
    GEMINI_API_KEY: "$GEMINI_API_KEY"
    # ⚠️ 指向 Issue Tracker 倉庫（gov-tender-fetcher）的 Project ID，不是本倉庫
    CI_PROJECT_ID: "$ISSUE_TRACKER_PROJECT_ID"
    # ISSUE_IID 不再需要：mcp_orchestrator.mjs 會主動查詢最新符合條件的 Issue
```

- 使用 pytest + pytest-asyncio
- 單元測試覆蓋率要求：核心業務邏輯 >= 80%

### 4.6 .agentic/architecture_rules.md

```markdown
# 架構柵欄 — Python FastAPI
# 定義強制分層規則，AI 產生的程式碼必須遵守，違反即為架構錯誤

## 強制三層架構
Router（api/v1/）→ Service（services/）→ Repository（repositories/）

### Router 層規則
- 只負責 HTTP 請求解析、回應序列化、路由定義
- 禁止直接操作資料庫（不得 import SessionLocal 或 AsyncSession）
- 禁止包含任何業務邏輯判斷
- 所有輸入必須透過 Pydantic Schema 驗證

### Service 層規則
- 負責業務邏輯，可跨 Repository 協調
- 禁止直接引用 SQLAlchemy ORM Model（只能透過 Repository 介面）
- 禁止直接處理 HTTP Request/Response 物件

### Repository 層規則
- 唯一允許操作 SQLAlchemy AsyncSession 的層
- 方法回傳值必須是 Schema 或 Python 基本型別，禁止回傳 ORM Model 實例
- 每個 Repository 只對應一個領域 Model

## 非同步規範
- 所有 I/O 操作（DB、HTTP、檔案）必須使用 async/await
- 禁止在 async 函式內呼叫任何同步阻塞操作（open、requests.get 等）
- CPU 密集運算使用 asyncio.run_in_executor 卸載至 ThreadPoolExecutor

## 錯誤處理規範
- 所有 HTTPException 必須在 Router 層拋出
- Service 層使用自訂 Domain Exception（繼承 Exception）
- 禁止直接 raise Exception（必須使用語意化自訂例外）
```

### 5.6 .agentic/architecture_rules.md

```markdown
# 架構柵欄 — Java Spring Boot

## 強制三層架構
Controller → Service（Interface + Impl）→ Repository（JPA）

### Controller 層規則
- 只負責 HTTP 請求映射、DTO 驗證、回應封裝
- 禁止注入 Repository Bean（只能注入 Service Interface，維持依賴反轉）
- 所有入參使用 @Valid + DTO 類別，禁止直接接收 Entity（安全邊界）
- 回傳統一使用 ResponseEntity<ApiResponse<T>>

### Service 層規則
- 必須定義 Interface（XxxService），實作放在 impl/ 子目錄（方便 Mock 測試）
- 禁止直接操作 Entity 並回傳給 Controller（必須先轉為 DTO）
- 跨 Service 依賴只能透過 Interface 注入
- 事務管理：@Transactional 只標注在 Service Impl 層

### Repository 層規則
- 繼承 JpaRepository 或 JpaSpecificationExecutor
- 複雜查詢使用 @Query（JPQL 優先，必要時才用 Native Query）
- 禁止在 Repository 中包含業務邏輯（單一職責）

## 實體設計規範
- 所有 Entity 繼承 BaseEntity（createdAt、updatedAt、isDeleted）
- 使用邏輯刪除（isDeleted flag），禁止實體刪除業務資料（保留稽核軌跡）
- Entity 間關聯使用 FetchType.LAZY，禁止 EAGER（避免 N+1 效能問題）

## 例外處理規範
- 全域例外處理：@RestControllerAdvice + @ExceptionHandler
- 自訂例外繼承 BusinessException（包含 ErrorCode 枚舉，方便前端對應處理）
- 禁止在 Service 層直接使用 ResponseEntity 或 HttpStatus（違反分層原則）

## Clean Code 規範
- 方法不超過 20 行，超過必須拆分（提升可讀性）
- 禁止使用魔術數字（Magic Number），統一定義在 Constants 類別
- 所有 public 方法必須有 Javadoc
```

### 6.6 .agentic/architecture_rules.md

```markdown
# 架構柵欄 — React TypeScript

## 強制 Feature-based 目錄架構
pages/（路由對應）→ features/（業務功能模組）→ components/（純展示 UI）

### Pages 層規則
- 每個 Page 只負責組裝 Feature 元件，不包含業務邏輯
- Page 元件本身不得直接呼叫 API（透過 Feature 的 Hook，保持 Page 薄）
- 禁止在 Page 中使用 useState 管理非 UI 狀態（例如載入中、資料）

### Feature 層規則
- 每個 Feature 目錄對應一個業務模組（例如 features/tender/）
- API 呼叫邏輯封裝在 features/[name]/api.ts（使用 React Query，統一快取策略）
- 業務狀態邏輯封裝在 features/[name]/hooks/
- Feature 元件禁止直接使用 axios，只能透過 api.ts 的封裝（統一錯誤處理）

### Components 層規則
- components/ 下只放純展示元件（Presentational Component）
- 純展示元件不得包含 API 呼叫或 Zustand store 讀取（保持可複用性）
- 所有 props 必須有 TypeScript Interface 定義

## TypeScript 規範
- 禁止使用 any，用 unknown 替代並配合型別守衛（Type Guard）
- API 回應型別定義在 features/[name]/types.ts
- 全域共用型別定義在 src/types/
- 禁止使用 as 強制轉型（必須有充分理由並附註釋，否則視為架構缺陷）

## 狀態管理規範
- 伺服器資料（來自 API）：只用 React Query，禁止存入 Zustand（避免資料來源不一致）
- 全域 UI 狀態（Modal 開關、主題）：使用 Zustand
- 表單狀態：使用 react-hook-form + zod，禁止手寫 onChange 處理

## 效能規範
- 所有頁面元件使用 React.lazy + Suspense 做 code splitting（加快初始載入）
- 禁止在渲染函式中直接建立物件或陣列（導致不必要重渲染）
- useMemo / useCallback 只在有效能問題時才加，禁止過度使用（增加複雜度）
```

## 7. Template 維護指南

### 7.1 引擎版本升級流程

三個 template 的 `.gitlab-ci.yml` 都會在 CI 執行期透過 `curl` 動態下載 `ai-engine` 倉庫裡固定版本的 `mcp_orchestrator.mjs`（見各 template 的 `.gitlab-ci.yml` 第 `ENGINE_VERSION` 行）。升級時：

1. 在 `ai-engine` 倉庫修改 `mcp_orchestrator.mjs` 內容，提交並推送
2. 重新打 tag（**tag 不會自動跟隨分支更新，必須重新打**）：

    ```bash
	git tag -d v1.0.0 
	git push origin :refs/tags/v1.0.0 
	git tag v1.0.0 
	git push origin v1.0.0
    ```

或改用新版本號（如 `v1.1.0`），則三個 template 的 `.gitlab-ci.yml` 都要同步把 `ENGINE_VERSION="v1.0.0"` 改成新版本號
3. 各業務專案重新觸發一次 Pipeline 驗證版本確實生效

### 7.2 新增技術棧 Template

以新增 Node.js Express 為例：

1. 在 `ai-template/` 下建立 `express/` 子目錄
2. 放入 `.gitlab-ci.yml`（`--tech-stack node`）、`.gitignore`、`CLAUDE.md`、`.agentic/` 韁繩文件
3. 在 `ai-engine` 的 `mcp_orchestrator.mjs` 的 `TECH_CONTEXT` 物件新增一行：

```js
const TECH_CONTEXT = {
    python: "...",
    java:   "...",
    react:  "...",
    node:   "特別注意：本專案為 Node.js Express 技術棧。...",
};
```

4. 在 `tools/server.js` 的 `TEMPLATE_META` 物件新增對應的顯示資訊：

```js
express: { emoji: '🟩', name: 'Node.js', sub: 'Express' },
```

5. 重新打 tag 發版（見 7.1）

### 7.3 各倉庫職責總覽

|倉庫|職責|需要動的時機|
|---|---|---|
|`ai-engine`|AI 自動化執行引擎|升級引擎邏輯、新增技術棧的 TECH_CONTEXT|
|`ai-template`|Template + 開新專案工具|更新韁繩規範、新增技術棧子目錄、工具更新|
|`{專案名稱}`（Issue Tracker）|需求協調中心，統一存放跨前後端的功能 Issue|開新需求、管理 Label 與 Milestone|
|各業務專案|業務程式碼 + 自己的 `.agentic/`|日常開發|

## 8. 開新專案操作流程

### 8.1 前置需求

|項目|說明|
|---|---|

### 8.2 每次使用流程

```bash
# 第一次：安裝依賴（之後不需要重複）
cd ai-template/tools
npm install

# 啟動工具
node server.js
```

開啟瀏覽器前往 `http://localhost:3000`，依照介面操作即可。

### 8.3 常見問題

**Q：`node server.js` 顯示 `Cannot find module 'express'`**

尚未安裝依賴，先執行 `npm install`。

**Q：瀏覽器顯示「無法連線」**

確認終端機仍在執行 `node server.js`（沒有按 Ctrl+C 關掉），再重整瀏覽器。

**Q：建立專案時顯示「目錄已存在」**

`{輸出路徑}/{專案名稱}` 的資料夾已經存在，換一個專案名稱或先刪除舊資料夾。

**Q：git push 失敗**

確認遠端倉庫已建立且為**空白**（不要勾選 Initialize README），並確認有對應的存取權限。

**Q：想新增第四種技術棧**

在 `ai-template/` 新增子目錄，同步更新 `tools/server.js` 的 `TEMPLATE_META`（參考第 7.2 節）。重啟 `node server.js` 後新卡片自動出現。
