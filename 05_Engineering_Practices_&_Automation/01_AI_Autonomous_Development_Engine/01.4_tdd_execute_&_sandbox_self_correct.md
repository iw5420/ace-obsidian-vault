在這個階段，Claude Code Pro 發揮其強大的 CLI 執行能力，但必須被限制在 Docker 沙盒中。

```
[Windows Host]
  Claude Code Pro (意圖驅動)
    │
    │ 1. 寫下測試 (Test First) & 實作程式碼
    ▼
┌────────────────────────────────────────────────────────┐
│ [Docker Container Sandbox]                             │
│   │                                                    │
│   ▼ 2. 執行校驗                                         │
│   mvn test-compile (編譯檢查)                          │
│   mvn test -Dtest=... (執行測試)                       │
│   │                                                    │
│   └─► [Pass] ──► 準備發 MR                             │
│   └─► [Fail] ──► 擷取 Log 傳回給 Claude Code 進行修正    │
└────────────────────────────────────────────────────────┘
```

- **Harness 規範（環境可讀性）**：
    
    - 不要讓 Claude 盲目猜測編譯錯誤。Windows 宿主機將專案目錄 Mount 進 Docker 容器。
        
    - Claude 修改完代碼後，透過 CLI 呼叫 `docker exec -it dev-sandbox mvn test`。
        
    - **所有的編譯器錯誤、Linter 警告、JUnit 失敗 Log，都必須結構化地導流回給 Claude Code 的 Context**。這就是環境可讀性——讓 AI 擁有極高精確度的反饋迴圈。
        
- **自我修正極限**：設定 `MAX_RETRY = 5`。若超過 5 次仍有測試失敗，Claude 停止執行，將當前錯誤的測試報告 Push 到分支，並在 GitLab Issue 上留言：`@Ace 遭遇非預期阻礙，已中斷退出，等待人類排解。`，標籤改為 `status::blocked`。
