## 🧭 1. 概念核心：為什麼我們需要端到端自動化驗證？

在軟體工程中，**E2E（End-to-End，端到端）** 驗證代表將系統中所有的零組件串聯在一起，進行**從輸入（原始起點）到輸出（最終終點）的完整流程演練**。

### ❓ 為什麼我們需要寫一個 `run_curation.py` 來做自動化壓測？

1. **驗證控制平面與數據平面的「閉環控制」**：我們在模組一寫了硬體偵測守門員，在模組二寫了去重管線。如果這兩個模組各過各的，就只是美麗的孤島。透過 E2E 驗證，我們能確保「動態偵測到的 12 核心（控制平面）」能完美且毫無阻礙地灌入「多進程去重引擎（數據平面）」，實現完美的動態調度。
    
2. **生產環境前的「無傷安全演習」**：在我們真正把幾百 GB 的真實語料送進昂貴的 GPU 叢集開始訓練之前，我們先在記憶體中利用 10,000 筆模擬數據進行壓力測試。這樣可以在幾秒鐘內抓出程式碼有沒有記憶體洩漏、多核心死鎖（Deadlock）或超參數衝突，拒絕讓髒代碼污染昂貴的算力。
    

## 🧠 2. 關鍵名詞大通解（配合老實人舉例）

為了讓你在架構思維上徹底通透，我們將這條端到端驗證管線涉及的全新核心技術，用最生活化的老實人比喻拆解出來：

### ① 端到端整合驗證 (End-to-End Validation)
- **硬核定義：** 對整個系統進行完整性測試，模擬資料從最初級輸入、流經所有中間處理模組、直到最終成品輸出的全鏈路流程，用以確保模組間的介面與控制流完全閉環。
- **老實人舉例：** 就像汽車出廠前的「整車動態測試」。我們不只單獨測試引擎或輪胎（單元測試），而是把整台車組裝好，實際開上測試賽道（執行 E2E 腳本），看看踩油門時變速箱有沒有順暢換檔、煞車有沒有及時作動，確保整台車開起來完全沒有物理衝突。
    
### ② 模擬私有文本語料庫 (Mock Dataset Generation)
- **硬核定義：** 在記憶體中動態構造具備特定統計分佈或特徵規律的測試數據集，用於在脫離真實環境時進行邏輯驗證與效能邊界測試。
- **老實人舉例：** 就像汽車工廠在做撞擊測試時使用的「假人模特兒」。我們不需要真的拿一個活生生的人（幾百 GB 的真實數據）去撞車，我們在記憶體裡動態用 `for` 迴圈捏造 10,000 筆帶有特定流水號的文本假人，就能安全、無傷且快速地測試出整條管線的安全氣囊（演算法）有沒有正常彈出。
    
### ③ 靜態組態與強型態守門員 (Hydra + Pydantic Pipeline Validation)
- **硬核定義：** 結合層級式配置管理與執行期型態校驗，在數據灌入管線前對硬體參數、超參數進行嚴格的合法性檢查，形成程式碼的防禦性邊界。
- **老實人舉例：** 就像高鐵站的「雙重安檢閘門」。第一道閘門（Hydra）負責檢查你的車票（YAML 設定檔與命令列覆蓋參數）是否完整對齊；第二道閘門（Pydantic）則像 X 光機，嚴格檢查你行李裡的物品（如 `optimal_threads` 是否為正整數、設備是否為合法的裝置名稱）。只要有任何一項不符合安全標準，當場直接攔截爆錯，絕不放行。
    

### ④ 峰值計算吞吐率 (Peak Throughput Rate)

- **硬核定義：** 數據管線在單位時間內所能處理的數據單元總量（例如 docs/sec 或 tokens/sec），是評估並行架構效能最重要的硬核指標。
    
- **老實人舉例：** 就像計算「高鐵檢票口的每分鐘通關人數」。你的管線開滿多核心狂飆，吞吐率算出 `11,706 docs/sec`，就代表這條自動化管線每秒鐘可以幫一萬多篇小說做完 DNA 提取和抄襲比對，這是衡量硬體效能有沒有被完全榨乾的實力鐵證。
    

## 🚀 3. 端到端管線的資料流與調度特質

在 `run_curation.py` 的自動化驗證中，整條管線呈現了極致的「無硬編碼（No Hardcoding）自適應控制流」：

```
[ 1. 執行啟動 ] ➔ python run_curation.py
       │
       ▼ (Hydra + OmegaConf 自動組網)
[ 2. 靜態配置載入 ] ➔ 融合 YAML、命令列覆蓋參數與預設值
       │
       ▼ (Pydantic model_validate 強型態介入)
[ 3. 動態硬體感知 ] ➔ 本地自動感知核心數(12)與設備類型('mps')
       │
       ▼ (資料平面火力全開)
[ 4. 多進程並行計算 ] ➔ 12 核心 P-Cores 無狀態分流清洗與 MinHash
       │
       ▼ (控制平面安全阻斷)
[ 5. 單執行緒 LSH 聚合 ] ➔ 主進程分桶碰撞，篩除重複件，計算衍生指標
       │
       ▼ (環境防禦日誌)
[ 6. 工業級報告輸出 ] ➔ 依設備自動對照翻譯，產出千分位對齊的中文 Performance 報表
```

在並行調度上，這套架構完美處理了「效能與秩序的權衡」：

- **前半段（無狀態計算）**：清洗與 MinHash 簽名計算，各篇文章互不干涉，屬於純粹的並行問題（Embarrassingly Parallel），因此直接開滿多進程（Workers）在不同的晶片核心上狂飆，將吞吐率推向峰值。
    
- **後半段（有狀態比對）**：LSH 雜湊桶聚合，必須知道前面進了什麼桶子。為了防止多核心之間為了搶奪同一個記憶體桶而頻繁加鎖（Lock Overheads）導致速度暴跌，架構師精明地將其收攏回單執行緒，在主進程中以極速完成過濾阻斷。
    

## 🎯 4. 模組二：核心觀念大對齊 (Architectural Digest)

當你向別人介紹或自己複習本篇的核心知識時，不需要去背誦複雜的架構圖，只需用以下經過高度濃縮的「一句話大白話」來掌握其精髓：

- **端到端整合驗證 (End-to-End Validation)**
    - **精髓濃縮：** 它是整個系統的「整車動態路試」。
    - **一秒說清楚：** 拒絕組件孤島，將組態、守門員、去重管線與日誌系統串成一條龍，確保數據從起點到終點的控制流與資料流完全閉環通暢。
        
- **模擬私有文本語料庫 (Mock Dataset)**
    - **精髓濃縮：** 它是系統壓測的安全「碰撞假人」。
    - **一秒說清楚：** 不碰觸、不傷害真實的高成本數據，在記憶體中用程式碼動態捏造 10,000 筆帶有流水號特徵的測試語料，用極低成本安全地測試出系統的效能邊界。
        
- **雙重安檢閘門 (Hydra + Pydantic)**
    - **精髓濃縮：** 它是管線啟動前的「防禦性守門員」。
    - **一秒說清楚：** Hydra 負責動態組網並把選單準備好，Pydantic 負責掃描裡面的變數型態是否安全。只要參數有任何不合法，當場熔斷報錯，絕對不讓髒組態浪費後半段的昂貴算力。
        
- **峰值計算吞吐率 (Throughput)**
    - **精髓濃縮：** 它是硬體產能的「實力驗收單」。
    - **一秒說清楚：** 用總處理量除以管線總秒數，動態算出每秒能處理多少筆 docs。這是衡量多核心有沒有被 100% 壓榨、演算法有沒有發生卡頓的核心性能指標。
        
- **多進進程混合調度 (Multiprocessing Pool)**
    - **精髓濃縮：** 它是兼顧速度與秩序的「兩階段並行哲學」。
    - **一秒說清楚：** 前半段清洗無狀態，直接開滿 12 核 P-Cores 瘋狂分流狂飆；後半段分桶比對有狀態，為了防止核心之間互相搶記憶體、加鎖打架，立刻收攏回單執行緒極速過濾。
        
- **去重率 (Mutation Rate)**
    - **精髓濃縮：** 它不是程式壞掉，而是數據集的「高同質化警訊」。
    - **一秒說清楚：** 當壓測跑出 99.99% 的去重率，代表你塞進去的一萬筆資料本質上全是同一筆復讀機垃圾。這項指標在實戰中是拿來評估「我們的去重引擎在面對惡意重複數據湧入時，有沒有實力在 1 秒內把它們全部阻斷」。
        
- **跨平台動態轉譯 (Cross-Platform Profiling)**
    - **精髓濃縮：** 它是程式碼放諸四海皆準的「環境防禦自適應」。
    - **一秒說清楚：** 優秀的架構不硬編碼硬體名稱。直接讀取模組一傳進來的 `device` 變數（如 `mps`, `cuda`, `cpu`），在執行期透過字典自動對照翻譯成高級中文字幕。程式碼在 Mac 認識 Apple Silicon，上雲端自動認識 NVIDIA。
